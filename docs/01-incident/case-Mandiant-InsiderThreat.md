# 침해사고 사례 분석 - Mandiant Insider Threat

---

## 개요
![전체 흐름](../images/incident/case-Mandiant/logo.png)
### 1. 사고 배경

해당 침해사례는 Mandiant가 실제 클라우드 침해 사례들을 기반으로 도출한 **해고 직원에 의한 내부자 위협 공격 패턴**입니다.

퇴직하는 직원의 모든 액세스 자격 증명(무단 또는 숨겨진 계정 포함)은 고용 종료 즉시 식별하고 철회되어야 합니다. 이 원칙이 지켜지지 않을 경우 전직 직원이 여전히 유효한 자격 증명이나 사전에 만들어 둔 비밀 계정을 이용해 퇴직 후 시스템에 재접근하는 시나리오가 발생합니다.

이 사고의 핵심 배경은 다음과 같습니다.

* **위협 주체 유형:** 해고된 전직 직원인 악의적 내부자
* **동기:** 조직에 대한 보복 및 파괴 의도
* **취약점:** 퇴직 후 CI/CD 서버 접근 자격 증명 미회수, 계정 미비활성화

### 2. 사고 요약

| 항목 | 내용 |
|------|------|
| 발생 시점 | 2020년 9월 |
| 공격자 | 해고된 전직 직원 |
| 초기 접근 방식 | 퇴직 전 보유한 CI/CD 서버 자격 증명 재사용 |
| 주요 행위 | CI/CD 서버 접근 → 신규 사용자 계정 생성 → 추가 자격 증명 탈취 |
| 최종 피해 | 운영 중인 프로덕션 데이터베이스 삭제 |
| 피해 유형 | 데이터 파괴, 서비스 중단, 복구 비용 발생 |

## 공격 분석

### 1. 공격 흐름

```
[해고 직원]
    │
    ▼
[기존 자격 증명으로 CI/CD 서버 접근]
    │  (퇴직 후 미회수된 계정 사용)
    ▼
[CI/CD 서버 내 신규 사용자 계정 생성]
    │  (지속적 접근 경로 확보-> 백도어 계정)
    ▼
[추가 자격 증명 탈취]
    │  (서버 내 저장된 시크릿, API 키, DB 접속 정보 등)
    ▼
[프로덕션 데이터베이스 삭제]
    │  (최종 파괴 행위)
    ▼
[서비스 중단 및 데이터 손실 발생]
```

### 2. 단계별 공격 프로세스

#### 1) 초기 접근 — 자격 증명 재사용

퇴직 직원이 여전히 활성화된 자격 증명이나 퇴직 전에 만들어 둔 비밀 계정을 사용하여 퇴직 후 시스템에 몰래 재접근합니다.

* 공격자는 재직 중 발급받은 CI/CD 서버 접속 자격 증명을 보유한 상태로 해고됨
* 조직이 오프보딩 절차에서 해당 계정을 즉시 비활성화하지 않아 접근 가능한 상태 유지
* CI/CD 서버는 코드 빌드 및 배포 자동화 파이프라인의 핵심으로 프로덕션 환경에 대한 광범위한 권한을 보유하는 경우가 많음

#### 2) 지속성 확보 — 신규 사용자 계정 생성

공격자는 MFA에서 면제된 관리자 계정을 생성하거나 장기 유효 액세스 토큰과 백도어 계정을 조용히 만들어 지속적인 접근 경로를 확보합니다.

* 기존 자격 증명으로 CI/CD 서버에 접근한 후 탐지 회피를 위한 신규 사용자 계정 생성
* 기존 계정이 나중에 비활성화되더라도 지속적인 접근이 가능하도록 백도어 계정을 심어 놓음
* 계정 생성 행위는 로그 모니터링이 없는 환경에서 즉각 탐지되지 않을 가능성이 높음

#### 3) 자격 증명 탈취

* CI/CD 서버는 구조적으로 빌드 스크립트, 환경 변수, 시크릿 저장소 내에 데이터베이스 접속 정보, API 키, 클라우드 IAM 자격 증명 등을 포함하는 경우가 많음
* 공격자는 이 자격 증명들을 탈취하여 데이터베이스에 직접 접근할 수 있는 권한을 획득
* CI/CD 파이프라인의 OIDC 연결 역할이 과도하게 허용된 경우 CI/CD 파이프라인 자체가 프로덕션 클라우드 환경의 핵심 접근 벡터가 됩니다.

#### 4) 최종 목표 — 프로덕션 데이터베이스 삭제

* 탈취한 자격 증명을 이용해 운영 중인 프로덕션 데이터베이스에 접근 후 삭제
* 복구 불가능한 데이터 손실 유발, 서비스 중단, 조직에 대한 최대 피해 극대화 의도
* 백업 부재 또는 백업 검증 미흡 시 데이터 영구 소실

## 대응 방안

### 1. 즉각 대응 절차

#### 1) 계정 및 접근 즉시 차단

* 공격자가 생성한 모든 신규 백도어 계정 즉시 비활성화
* CI/CD 서버, 클라우드 콘솔, 데이터베이스에 대한 모든 활성 세션을 강제로 종료
* 탈취된 것으로 의심되는 모든 자격 증명, API 키, 시크릿을 즉시 교체
* 퇴직 직원의 모든 자격 증명을 즉시 식별하고 철회해야 합니다.

#### 2) 피해 범위 파악

* CI/CD 서버의 감사 로그를 수집 및 보존하여 포렌식 증거 확보
* 삭제된 데이터베이스의 범위를 파악하여 어떤 DB가, 언제, 어느 정도 삭제되었는지 확인
* 공격자가 탈취한 자격 증명으로 접근한 모든 시스템 및 리소스 목록 작성

#### 3) 복구 절차 개시

* 가장 최신의 백업을 특정하고 격리된 환경에서 복원 테스트
* 백업이 공격자에 의해 오염되거나 삭제되지 않았는지 무결성 검증 선행
* 복구 완료 전까지 해당 서비스의 임시 중단 또는 대체 운영 방안 마련

#### 4) 내부 보고 및 법적 대응 준비

* CISO, 법무팀, HR 등 관련 이해관계자에게 즉시 상황 보고
* 내부자 위협은 형사 고소 가능성이 있으므로 디지털 포렌식 증거 보전 필수 (로그, 접속 기록, 계정 생성 기록)

### 2. 사후 조치 및 재발 방지

#### 1) 퇴직자 오프보딩 프로세스 강화 — SSO & IdP 연동

* **SSO 도입:** CI/CD 서버, 클라우드 콘솔, DB 접근 등 모든 시스템을 SSO로 통합하여 IdP 계정 비활성화 한 번으로 전체 접근 동시 차단
* **HR↔IdP 자동화 연동:** 인사 시스템에서 퇴직 처리 시 Okta, Azure AD 등 IdP 계정이 자동 비활성화되도록 프로비저닝 파이프라인 구성
* SSO 미구축 환경에서는 시스템별 계정이 분산되어 오프보딩 시 누락이 발생하기 쉬워 이번 사고와 같은 상황이 반복됨

#### 2) 백도어 계정 생성 차단 — IdP 중앙화

공격자가 CI/CD 서버 내에서 직접 신규 사용자 계정을 생성한 것이 2단계 공격이었습니다.

* **계정 생성 중앙화:** 모든 계정은 반드시 IdP를 통해서만 생성 가능하도록 정책 수립. CI/CD 서버 로컬에서 직접 생성된 계정은 즉시 이상 탐지 대상으로 분류
* **MFA 강제 적용:** IdP 레벨에서 CI/CD 서버 포함 모든 시스템 접근에 MFA 정책 강제
* **신규 계정 생성 알림:** IdP 외부에서 계정 생성 이벤트 발생 시 실시간 Alert 설정

#### 3) 프로덕션 DB 삭제 행위 차단 — SCP

탈취된 자격 증명으로 로그인에 성공하더라도 SCP로 고위험 API 호출 자체를 조직 레벨에서 차단하면 최종 피해를 막을 수 있습니다.

* **고위험 API 차단 SCP 적용:** DeleteDBInstance, DropDatabase 등 파괴적 API 호출을 프로덕션 OU에서 명시적으로 Deny
* **SCP는 IAM 권한 위에서 작동:** 탈취된 자격 증명이 관리자 권한을 가지고 있어도 SCP로 설정된 제한은 우회 불가
* **Deletion Protection 활성화:** AWS RDS Deletion Protection 등 서비스 레벨 보호도 병행 적용

```
[조직 레이어 구조]
AWS Organizations (Root)
  └── SCP: DeleteDBInstance Deny 적용
        └── Production OU
              └── 프로덕션 계정
                    └── 탈취된 자격 증명으로 접근해도 삭제 불가
```

#### 4) 이상 접근 컨텍스트 탐지 — IDC / Zero Trust

퇴직 처리된 계정이거나 평소와 다른 접근 패턴이 탐지될 경우 자동으로 차단 또는 추가 인증을 요구합니다.

* **Identity-Aware Proxy 적용:** CI/CD 서버 접근 시 단순 자격 증명 외에 접근 컨텍스트(시간대, 지역, 디바이스 상태 등)를 함께 검증
* **비정상 접근 시나리오 탐지:**
  * 퇴직 처리 후 계정 접근 시도
  * 평소와 다른 IP 대역·국가에서의 접근
  * 업무 외 시간대 CI/CD 서버 접근
* **UEBA(User and Entity Behavior Analytics) 연동:** 위 이상 패턴 탐지 시 자동 세션 차단 및 보안팀 알림

#### 5) CI/CD 파이프라인 보안 강화

* CI/CD 서버에 저장된 모든 시크릿을 전용 시크릿 관리 솔루션으로 이관 (HashiCorp Vault, AWS Secrets Manager, GCP Secret Manager 등)
* CI/CD 파이프라인에서 OIDC 연결 역할에 과도한 권한이 부여되지 않도록 최소 권한 원칙을 적용해야 합니다.

#### 6) 프로덕션 데이터 보호

* 프로덕션 DB에 대한 정기적 백업 수행 및 백업 복원 테스트 의무화
* 공격자가 백업된 것을 삭제하지 못하도록 백업 저장소를 프로덕션 환경과 네트워크적으로 격리된 별도 계정/구역에 저장
